# Siyo 0.9 Syntax Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the declarative Siyo VS Code extension in line with Siyo compiler 0.9.0 syntax, with real tokenization regression tests, snippets, docs, and a deterministic test/package/CI/release pipeline. Ship it as extension version 0.2.0.

**Architecture:** The extension stays purely declarative: a TextMate grammar, a language configuration and a snippets file, with no runtime code and no LSP. The tests load the shipped grammar through `vscode-textmate` and `vscode-oniguruma`, the same engine VS Code uses, and assert on the scopes of real Siyo sources. CI runs `npm ci`, the tests, packaging and a check of the VSIX contents. The release workflow publishes that same VSIX to each registry only when that registry's token is configured, and records any registry it skips in the job summary.

**Tech Stack:** TextMate JSON grammar, Node 22 (`.nvmrc`; vsce 4 and ovsx 1.3 require it) with `node:test`, vscode-textmate 9.3.2, vscode-oniguruma 2.0.1, @vscode/vsce 4.1.0, ovsx 1.3.0 and yaml 2.9.1 (exact versions, locked by `package-lock.json`), and GitHub Actions.

## Derived syntax facts (what the grammar must encode)

- **Comments:** `//` line comments only. The lexer has no block comments.
- **Keywords (SyntaxRules.getKeywordType):** true false imut mut if else while for fn return as impl self scope spawn actor break continue struct enum import java new try catch in null match send type throw pub do interface.
  - **Contextual:** `send` is a keyword only as a statement prefix and is otherwise a name. `type` is a keyword only in `type Name =` or `type Name<..> =` and is otherwise a name. These are the only two the parser accepts as names (`isContextualKeywordName`).
  - **Reserved:** `new` and `java` are reserved everywhere. `new` is valid only after `fn` or `.`, and `java` only after `import`.
- **Strings:**
  - `"..."` cannot span lines.
  - `"""..."""` may span lines.
  - Valid escapes: `\n \r \t \\ \" \0 \$ \{ \}`. Any other escape is reported by the lexer.
  - Interpolation is `$name` (a letter or `_` after `$`) or `${expr}` with nested braces. A `$` followed by anything else is literal.
  - The old `{expr}` form is gone: a bare `{` in a string is plain text.
- **Numbers:** decimal `42`, hex `0xFF`, long suffix `L`/`l` (`9000000000L`, `0xFFL`), and float `3.14`, which needs digits on both sides of the dot. There is no exponent form and no `..` operator; `DoubleDotToken` is lexed but never parsed.
- **Operators:** `+ - * / %`, `== != < <= > >=`, `&& || !`, `& | ^ ~ << >>`, `= += -= *= /=`, `->`, `=>`, `#{` (set literal), `.`, `as`.
- **Types (TypeResolver):**
  - Built-in names: int long float bool string object any channel map set fn.
  - Generic names: `Array<T>`, `List<T>`, `Map<K,V>`, `Set<T>`.
  - Arrays are written `T[]`. Function types are written `fn(int) -> int`. `double` is **not** a type.
- **Declarations:**
  - `fn name<T>(..) -> T`, with `mut` allowed on parameters.
  - `struct`, `actor [struct]`, `enum E { A = 10, B }`, `type R = Ok(int) | Err(string)`, `interface I { fn m() -> T }`, `impl S`, `impl I for S`, and the `pub` prefix.
  - `import "m" [as a]` and `import java "x.Y"`.
- **Statements:** `do { } while c`, `for mut i = 0 i < n i = i + 1 { }`, `for x in xs { }`, `throw e`, `try { } catch e[: T] { }`, `scope { }`, `spawn { }`, `spawn X.new()`, `send a.m()`.
- **Match:** `match v { Ok(x) => .., R.Err(_) => .., _ => .. }`.
- **Documented built-ins (GRAMMAR.md ∩ BuiltinFunctions):**
  - Text and conversion: len toString toInt toDouble toFloat toLong parseInt parseFloat parseLong substring contains indexOf startsWith endsWith replace trim toUpper toLower split chr ord.
  - Collections and functions: push pop removeAt sort map filter reduce forEach set channel range.
  - I/O and errors: print println input error.
  - Reflection: fields field setField toMap typeName typeOf.
  - Other: random httpGet httpPost canRead.
  - `actorHandle` is internal and undocumented, so it is excluded.

## Global Constraints

- The extension version is `0.2.0`, the license is MIT, the publisher stays `SiyoLang`, and `engines.vscode` stays `^1.75.0`.
- No LSP, diagnostics or IntelliSense claims anywhere.
- No changes to the compiler. No push, merge, tag or publication from this session.
- Builds are deterministic: `npm ci` from a committed lockfile, exact devDependency versions, and the Node version pinned in CI.
- Workflows never reference `secrets.*` in an `if:`. A credentials step receives the tokens and emits `ovsx`/`vsce` booleans as step outputs, and each token is exposed only to that step and to its own publish step.

## Review Focus

1. **Unterminated `"` string:** highlighting must stop at the end of the line, as the lexer does, and must not bleed into the following lines. Test: `strings › unterminated string ends at end of line`.
2. **`${ {"k": 1}["k"] }`, a map literal inside an interpolation:** the inner `}` must not close the interpolation. Test: `interpolation › nested braces`.
3. **`send` and `type` used as names:** `ch.send(x)`, `fn send(..)`, `mut type = 1` and `type = "GET"` must not be highlighted as keywords. Test: `contextual keywords`.
4. **A comparison that looks like a generic:** in `if a < b || c > d`, the `<` must not open a type-argument scope. Test: `generics › comparison is not generic`.
5. **Release with only `OVSX_PAT` set:** Open VSX publishes, the Marketplace is skipped with a summary line, and the job stays green. Owned by Task 4, which is checked by inspecting the workflow YAML because Actions cannot run locally.
